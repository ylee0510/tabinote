# ゲストモード（お試し機能）設計

**日付**: 2026-06-02  
**対象**: index.html（単一ページアプリ）

## 概要

未ログインユーザーがデモデータでアプリを試せるゲストモードを追加する。ログイン画面に「ログインせずに試す」ボタンを追加し、クリックするとワールドカップ2026のサンプル旅行データでアプリが起動する。保存・編集操作をしようとするとトーストで「💡 保存するにはログインが必要です」と案内する。

## ゲスト開始フロー

1. ログイン画面の「Googleでログイン」ボタンの下に「ログインせずに試す →」リンクを表示
2. クリック → グローバル変数 `isGuest = true` をセット → デモデータを `trips` にセット → `render()` を呼ぶ
3. アプリが通常通り起動し、デモ旅行が表示される

## 保存操作のガード

以下の全書き込み関数の先頭に `if(isGuest){ toast("💡 保存するにはログインが必要です"); return; }` を追加する:

- `createTrip()`
- `deleteTrip()`
- `upd()`（行程・荷物・予算・地図など全ての更新の基底関数）
- `addCheck()`
- `addPlace()`
- `confirmPin()`
- `saveTpl()`
- `addBudgetItem()`

`upd()` をガードすれば、それを経由する全操作（`addItin`, `delItin`, `toggleCheck`, `updateBudgetField` など）は連鎖的にガードされる。

## ゲスト時のヘッダー表示

ヘッダー下部に薄いバナーを1行表示：
```
「👤 ゲストモード｜ログインすると旅行を保存できます　[ログイン]」
```
- 背景: `#f4f4f5`、文字: `var(--muted)`、フォントサイズ: 11px
- 「[ログイン]」をクリックすると `showLoginModal = true` でログインモーダルを表示、**またはログイン画面に戻る**（実装コストが低いためログイン画面に戻る方式を採用）

## ログイン後の切り替え

`auth.onAuthStateChanged` でユーザーが検出されたとき:
- `isGuest = false`
- `trips = []`（デモデータをクリア）
- 通常のFirestoreリスナーを起動
- `render()`

## 非変更範囲

- Firebase認証・Firestore連携ロジック（ログイン後は変更なし）
- isViewOnly（共有リンク閲覧）の動作
- スマホ・PC両方のレイアウト

## render() の変更

```js
// 変更前
if(!user){ap(app,renderLogin());return;}

// 変更後
if(!user && !isGuest){ap(app,renderLogin());return;}
```
